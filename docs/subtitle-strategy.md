# 음성 대사 자막 추가 전략

> 2026-08-01 갱신: 미국판에 정식 이벤트 기반 자막 엔진과 시간표가 확인되었다.
> 이후 구현의 정본은 `docs/usa-subtitle-engine-comparison.md`이며, 기존 Key On
> 오버레이는 비교 진단 자료로만 유지한다.

조사 기준은 일본판 `SLPM-86020` 원본이다. 현재 단계의 결론은 **자막 추가가
가능하지만, 기존 문자열 교체가 아니라 음성 재생 루틴에 새 화면 표시 기능을
연결해야 한다**는 것이다.

## 확인된 사실

- 사용자가 한 스토리 루트를 끝까지 확인한 결과, 진행 중 대사는 음성만 나오며
  화면 자막은 없다.
- 일시 정지와 승패 결과에도 대사 텍스트가 없다.
- 루트 마지막 문구만 별도의 TIM 그래픽이며, 기존 그래픽 패치 경로로 처리됐다.
- `SE3`과 `SE4`에서 캐릭터/루트 이름을 가진 VAB 음성 뱅크 54개가 확인됐다.
  - `SE3`: 27개 뱅크, 49개 VAG
  - `SE4`: 27개 뱅크, 55개 VAG
- 예:
  - `SE3/KAN0WIN.01`
  - `SE3/LOT2WIN.05`
  - `SE3/MIK1WIN.17`
  - `SE4/HOT4WIN.03`
  - `SE4/TAT3WIN.00`
  - `SE4/UTS5WIN.14`
- 파일 선두 8바이트 뒤에 표준 PlayStation VAB 식별자 `pBAV`가 있다.
  Sony 문서가 설명하는 VAB는 여러 VAG 파형과 프로그램/톤 속성을 묶는 음원
  뱅크다.
- 뱅크 하나에 VAG가 여러 개 들어 있는 경우가 많다. `TAT3WIN.00`은 VAG 5개,
  `KAN0WIN.14`는 VAG 4개다. 따라서 파일명만으로 대사 한 줄을 식별할 수 없다.
- 정확한 ASCII 파일명 `KAN0WIN`, `TAT3WIN`, `UTS5WIN`은 디스크의 다른
  논리 파일에서 발견되지 않았다. 게임이 전체 파일명을 문자열로 보관하지 않고
  번호/테이블 또는 ISO 디렉터리 순서로 선택할 가능성이 높다.
- `STR/R_*.STR`, `STR/E_*.STR`은 Form 1과 Form 2가 섞인 스트림이다. 일반적인
  PS1 STR은 영상 섹터와 XA-ADPCM 음성 섹터가 교차할 수 있으므로, VAB 대사와
  같은 방식으로 단정하지 않는다.

전수 결과의 정본은 `work/analysis/vab_bank_audit.json`, 파일명 검색 결과는
`work/analysis/voice_filename_refs.json`이다. 재조사 도구는
`workspace/scripts/audit_vab_banks.py`다.

## 권장 구조

### 1. 음성 재생 이벤트를 자막의 기준으로 사용

가장 좋은 훅 위치는 CD 섹터 읽기나 SPU의 최종 Key On 레지스터가 아니라,
게임이 VAB의 프로그램/톤/VAG를 선택해 재생시키는 상위 함수다.

자막 키는 최소한 다음 정보가 필요하다.

```text
(스토리/루트 또는 뱅크 ID, 프로그램 번호, 톤 또는 VAG 번호)
    -> (자막 ID, 표시 지연, 최대 표시 시간, 종료 조건)
```

저수준 SPU Key On만 잡으면 효과음까지 섞이고 어떤 루트의 대사인지 잃기 쉽다.
반대로 상위 재생 함수에서는 뱅크 문맥과 내부 인덱스를 함께 얻을 가능성이 높다.

### 2. 한국어는 미리 그린 자막 아틀라스로 표시

이 게임에는 재사용 가능한 일반 문장용 글꼴 엔진이 아직 확인되지 않았다.
첫 PoC는 새 한글 글꼴 렌더러보다 다음 방식이 안전하다.

1. 번역문을 두 줄 이내의 고정 크기 PNG로 생성한다.
2. PS1용 4bpp 또는 8bpp TIM 아틀라스로 변환한다.
3. 음성 시작 시 해당 자막 사각형을 VRAM에 올리거나 이미 올라간 아틀라스에서
   선택한다.
4. 화면 하단에 반투명 또는 불투명 배경띠와 텍스처 사각형을 그린다.
5. 다음 음성, 음성 종료, 장면 전환, 스킵 시 즉시 지운다.

VRAM의 빈 위치는 추측하지 않는다. 스토리 장면에서 실제 VRAM 배치를 캡처하고,
충돌하지 않는 영역과 CLUT 위치를 정한 뒤 사용한다.

### 3. 종료 시점은 음성과 묶어 처리

고정 프레임 수만 사용하면 에뮬레이터 속도, 대사 중단, 장면 스킵에서 어긋난다.
우선순위는 다음과 같다.

1. 게임의 음성 종료/Key Off 함수에서 자막을 지운다.
2. 종료 이벤트가 없으면 VAG 길이와 톤의 재생 주파수로 시간을 계산한다.
3. 첫 PoC에서만 안전한 최대 표시 시간을 보조값으로 둔다.

새 음성이 시작되면 기존 자막을 교체하고, 전투나 메뉴로 전환되면 강제로
지우는 정리 경로가 반드시 필요하다.

### 4. STR 영상 대사는 별도 트랙으로 관리

STR에 포함된 대사가 있다면 두 선택지가 있다.

- 영상 프레임에 자막을 입혀 다시 인코딩하고 원래 섹터 인터리브를 보존한다.
- STR 재생 중에도 같은 런타임 자막 오버레이를 호출한다.

영화의 수가 적다면 첫 방식이 단순하다. 공통 자막 시스템이 완성되고 정확한
프레임 이벤트를 얻을 수 있다면 두 번째 방식이 용량 면에서 유리하다. VAB PoC가
성공하기 전에는 STR을 재인코딩하지 않는다.

## 구현 순서

### 단계 A — 음성 카탈로그

1. 54개 스토리 VAB를 개별 VAG로 분리한다.
2. 각 샘플에 `bank`, `program`, `tone`, `vag`, 길이, 화자, 일본어 받아쓰기,
   한국어 번역 필드를 부여한다.
3. 실제 플레이 순서와 카탈로그 ID를 대조한다.

뱅크 파일명만으로 줄을 매기면 안 된다. 한 뱅크 안의 내부 인덱스를 반드시
보존한다.

### 단계 B — 재생 함수 찾기

1. 알려진 뱅크 하나가 로드될 때 CD 읽기와 SPU 전송 지점을 잡는다.
2. 호출 스택을 거슬러 뱅크/프로그램을 선택하는 상위 함수를 찾는다.
3. 동일 함수가 다른 캐릭터와 다른 내부 VAG에도 사용되는지 확인한다.
4. 장면 오버레이가 바뀌어도 훅 주소가 유지되는지 확인한다.

정확한 파일명 검색이 0건이므로 문자열 참조만 기다리지 않고, 알려진 파일 LBA의
읽기와 VAB 헤더 `pBAV` 처리 지점을 런타임에서 추적한다.

### 단계 C — 한 줄 PoC

`SE4/TAT3WIN.00`의 내부 음성 하나처럼 재현하기 쉬운 이벤트를 고른다.

통과 조건:

- 목표 음성에만 테스트 한글 자막이 나타난다.
- 다른 VAG와 효과음에는 나타나지 않는다.
- 음성 시작과 표시 시작이 맞는다.
- 다음 음성/스킵/장면 전환에서 잔상이 남지 않는다.
- 음성 재생, 전투 진입, 프레임 진행에 이상이 없다.
- DuckStation 재진입 후에도 동일하다.

### 단계 D — 전체 적용

PoC 통과 후에만 전체 대사를 받아쓰고 번역한다. 자막 테이블과 아틀라스는
원본 파일의 빈 공간을 임의로 덮지 않는다. `DUMMY.DAT`도 실제 미사용 여부와
로더 접근 방식을 확인하기 전에는 저장소로 간주하지 않는다.

## 한 줄 런타임 PoC (2026-07-31)

타츠미 스토리에서 확인한 음성 요청은 `PC=0x8003E798`, 음성 ID `0x7C`,
호출 복귀 주소 `0x80045A9C`다. 이를 기준으로 다음 PoC를 만들었다.

- 빌더: `workspace/scripts/build_subtitle_poc.py`
- 실행 파일: `build/subtitle_poc/Bushido Blade (Japan) [KO Subtitle PoC].cue`
- 정적 검증 보고서: `build/subtitle_poc/build_report.json`
- 목표 표시: 화면 하단 중앙 `자막 테스트`, 100프레임
- 이벤트 훅: `0x80045A94`의 기존 `jal 0x8003E798`을 래퍼로 교체
- 프레임 훅: 메인 루프의 프레임 제출 호출 `0x8004322C`를 감싸 자막 프리미티브 삽입

자막 글자는 별도 VRAM 텍스처가 아니다. 글자 마스크의 가로 구간을 세로로 병합한
흰색 `TILE` 프리미티브 60개와 검은 배경 1개를 게임의 현재 오더링 테이블
포인터 `0x800A3010`에 연결한다. 프리미티브는 프레임 버퍼 인덱스에 맞춰 2세트를
두므로 GPU가 이전 프레임을 읽는 동안 태그를 재사용하지 않는다. 이 방식은 첫
PoC에서 VRAM 빈 공간을 추측하지 않아도 된다는 장점이 있지만, 전체 대사에는
프리미티브 수가 많으므로 성공 후 텍스처 아틀라스 방식으로 교체해야 한다.

첫 빌드는 `SLPM_860.20`을 `0x800A3000` 뒤로 확장했으나 로딩 화면에서
Reserved Instruction 예외가 발생했다. 정지 상태의 PC는 BIOS 예외 벡터
`0x000000A0`였고, `0x800A3000` 일대는 실제로 렌더 상태와 전역 변수가 사용하고
있었다. 따라서 실행 파일 뒤의 ISO 여유 섹터가 곧 안전한 RAM은 아니라는 가설을
폐기했다.

수정 빌드는 실행 파일 크기를 바꾸지 않는다. 정상 경로에서 필요하지 않은 PsyQ
GPU/CD/SPU 진단 문자열 영역 `0x800118B4–0x800120D0` 중 1008바이트에 래퍼와
압축 사각형 테이블을 넣었다. 이 영역은 원본과 타이틀/목표 스토리 RAM 캡처가
일치했다. 프레임별 패킷은 두 캡처에서 모두 0이었던 `0x80122000`부터 1952바이트를
사용한다. 이는 한 줄 PoC에만 허용한 조건부 공간이며 전체 게임에서 미사용으로
확정한 것은 아니다.

수정본은 DuckStation 부팅 후 `PC=0x80043224`, `cause=0`을 확인했고, 두 훅과
`0x800118B4`의 삽입 코드가 RAM에 유지되는 것도 확인했다. 로딩 예외는 해소됐지만
목표 대사에서의 실제 자막 출력 판정은 아직 보류한다.

첫 정상 부팅본으로 타츠미 엔딩까지 진행했으나 화면 자막은 나타나지 않았다.
엔딩 상태 RAM에서는 프리미티브 버퍼 1952바이트 중 724바이트가 실제 `TILE`
패킷으로 채워져 있었다. 따라서 음성 ID `0x7C` 이벤트 훅과 패킷 생성은 모두
실행됐고, 실패 지점은 화면 제출 순서였다.

기존 `0x80045CE0` 훅은 한 프레임에 여러 번 호출되는 처리 함수라 동일 패킷을
반복 연결하고 100카운트를 한 프레임 안에 소모할 수 있었다. 이 훅은 폐기했다.
새 훅은 메인 루프가 장면 콜백을 끝낸 뒤 프레임 제출을 시작하는
`0x8004322C`의 `jal 0x80070838`을 래퍼로 교체한다. 래퍼는 자막을 한 번 연결한
뒤 원래 함수를 호출하므로 프레임당 정확히 한 번 실행된다. 새 빌드는 정적 검증과
부팅 검증을 통과했으며 목표 대사 출력은 다시 확인해야 한다.

프레임 훅 수정본도 화면에는 나타나지 않았다. RAM 패킷을 다시 해석한 결과
명령 본문은 `0x60FFFFFF`로 올바른 흰색 `TILE`이었지만 DMA 태그가
`0x00xxxxxx`였다. 동적 생성 코드가 태그를 0으로 초기화해 GPU 명령 길이가 0이
되었기 때문이다. `TILE`은 세 워드이므로 태그 상위 바이트를 `0x03`으로 수정했다.

수정 후 DuckStation 타이틀 화면에서 GDB로 타이머를 강제 설정해 렌더 경로를
분리 검증했다. 프레임 진행 후 타이머가 감소했고, 첫 패킷은
`tag=0x0308A56C`, `command=0x60FFFFFF`로 확인됐다. 현재 사용자 화면에는 장시간
진단 표시가 켜졌다. 사용자가 화면 하단의 `자막 테스트`가 보인다고 확인해 렌더링
경로는 통과했다. 강제 타이머를 다시 0으로 지웠으며, 남은 검증은 목표 음성
ID `0x7C`가 자동으로 타이머를 켜는지 여부다.

자동 이벤트 시험 결과 `자막 테스트`는 실제 대사 위치가 아니라 대전 중에
나타났다. 따라서 `a0=0x7C`는 대사 고유 키가 아니며 전투 사운드에서도 재사용된다.
렌더링 PoC는 성공했지만 이벤트 식별 PoC는 실패했다. 실행 중인 시험본에서는
타이머를 0으로 지우고 `0x80045A94`를 원본 `jal 0x8003E798` 바이트
`E6 F9 00 0C`로 복구했다. 다음 실제 대사 직전부터 `a0–a3`, 복귀 주소,
현재 VAB 뱅크/스토리 상태를 함께 캡처해야 한다. 전체 적용 키는 최소한
`(뱅크 또는 스토리 문맥, 사운드 ID, 추가 인수)`가 되어야 한다.

이후 사용자가 추출된 106개 WAV를 청취해 전부 대사라고 확인했다. 따라서
효과음/대사를 런타임 공용 ID에서 다시 분류하는 작업은 중단한다. 자막 대상은
`voice_catalog.csv` 전체이며, 재생 조건은 각 행의 VAB 뱅크와 프로그램/톤/VAG
좌표로 직접 연결한다.

런타임 통과 조건은 목표 음성에서만 자막이 나타나고 약 100프레임 뒤 사라지며,
음성·전투 진입·장면 진행에 이상이 없는 것이다. ID `0x7C`만 비교하는 것은 PoC
범위이며, 전체 적용 전에는 뱅크/스토리 문맥을 함께 비교해야 한다.
