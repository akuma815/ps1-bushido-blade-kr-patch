# 초기 조사

## 범위와 기준선

- 대상은 일본판 단일 디스크 `SLPM-86020`이다.
- 원본 BIN은 510,021,792바이트이며 SHA-256은
  `7D89B9254C5001AD7FC4F0C2FC3CDA9600417D075292C34D3B60AA3B600DBA96`이다.
- CUE는 단일 `MODE2/2352` 트랙을 선언한다.
- 이 문서의 정적 조사는 원본을 수정하지 않고
  `workspace/scripts/inspect_psx_disc.py`로 수행했다.

## 확인된 사실

### 디스크와 실행 파일

- ISO 9660에서 디렉터리 18개, 파일 349개가 확인됐다.
- 논리 파일 크기 합계는 442,975,752바이트다.
- `SYSTEM.CNF`는 `cdrom:\SLPM_860.20;1`을 부팅한다.
- 실행 파일은 604,160바이트 PS-X EXE다.
- 진입 PC는 `0x80070A1C`, 적재 주소는 `0x80010000`,
  적재 payload 크기는 `0x93000`이다.
- 데이터 파일은 주로 `DATA0`~`DATA7`, `SE0`~`SE5`,
  `BIN0`~`BIN1`에 나뉜다.
- `STR` 13개와 `XA` 4개는 Mode 2 Form 1/Form 2가 섞인 스트림이다.
  일반 ISO 재작성 도구로 평탄화하면 안 된다.
- 63,072,000바이트 `DUMMY.DAT`가 있다. 빈 공간 또는 확장 공간으로
  간주하지 않는다.

### 텍스트와 그래픽 후보

- PS-X EXE 파일 오프셋 `0x1EE4`, `0x1F28`에서 Shift-JIS
  `ブシドーブレード`가 확인됐다. 대응 적재 주소는 각각
  `0x800116E4`, `0x80011728`이다.
- 첫 문자열은 `ブシドーブレード　［対戦モードにカッツェ見参！］`
  일부다. 메모리카드 제목 등 시스템용 문자열일 가능성이 높아,
  게임 본문 렌더러의 대표 증거로 쓰지 않는다.
- 1MB 이하 파일의 일반 Shift-JIS 스캔은 바이너리 오탐이 매우 많았고,
  확실한 대량 평문 대사 저장소는 아직 확인되지 않았다.
- 여러 `DAT`에서 TIM 헤더처럼 보이는 패턴이 발견되지만 현재 검출은
  구조 검증 전 후보다. 유효 TIM 블록 수로 해석하지 않는다.
- `DATA3/O16.DAT`, `DATA3/O17.DAT`는 각각 8,192바이트다.
  16×16 1bpp와 8×8 4bpp 고정 셀로 렌더한 결과 글꼴 표가 아닌 반복
  그래픽으로 보였다. 이 두 파일을 폰트로 채택하지 않는다.
- `DATA5/T0.DAT`, `DATA5/T1.DAT`는 각각 11,028바이트이며,
  앞부분이 32비트 오프셋과 좌표형 레코드처럼 보인다. 문자표라는
  증거는 아직 없다.

## 현재 가설

| ID | 가설 | 상태 | 다음 판정 |
| --- | --- | --- | --- |
| H-01 | 메뉴·인명·무기명 다수가 TIM 또는 커스텀 그래픽에 구워져 있다 | 유력, 미확정 | 유효 TIM 파서와 화면 대응표 작성 |
| H-02 | 일부 시스템 문자열만 Shift-JIS 평문이며 주요 화면은 별도 경로다 | 유력, 미확정 | 런타임 VRAM 업로드와 파일 읽기 경로 추적 |
| H-03 | 일본판의 기존 2바이트 코드 공간과 글리프 슬롯 일부를 한글에 재사용할 수 있다 | 미확정 | 실제 코드→글리프 소비자와 전체 참조 조사 |
| H-04 | 스토리 대화는 음성 중심이라 전체 한글화에는 별도 자막 경로가 필요하다 | 미확정 | 스토리 모드 화면·STR 재생 구간 실기 조사 |
| H-05 | 파일을 이동하면 숨은 LBA 참조가 깨질 수 있다 | 위험 신호 | 미국판 비교와 런타임 CD 읽기 추적 |

## 런타임 조사 상태

Mednafen 기반 PS1 디버거로 실행 계획을 만들었지만 현재 환경에는
어댑터 바이너리가 없어 실행하지 못했다. 따라서 메뉴·스토리 화면의 실제
텍스트 경로는 아직 런타임 확인 전이다. 정적 조사만으로 한글 표시 성공을
주장하지 않는다.

## 선행 PS1 프로젝트에서 확인한 재사용 원칙

- FF7Tools는 일반 문자열, 글꼴, TIM에 구운 UI, 압축 자산, 영상 자막을
  서로 다른 경로로 취급한다.
- Wild Arms 도구는 추출·재삽입과 글꼴 이미지/코드표를 분리하며,
  기존 문자 범위를 벗어나는 언어는 새 글꼴 이미지와 명시적 코드 매핑이
  필요함을 보여 준다.
- PS1 TIM은 픽셀, 선택적 CLUT, VRAM 좌표를 포함할 수 있으므로 PNG만
  바꾸는 것으로 끝내지 않고 원본 비트 깊이·팔레트·좌표를 보존해야 한다.
- XA/STR가 섞인 디스크는 해당 섹터 형식을 보존하는 추출·재빌드 도구를
  사용해야 한다.

## DuckStation 1차 런타임 캡처 (2026-07-29)

- 일본판 `SLPM-86020`이 DuckStation 0.1.11621에서 부팅·메뉴 진입됨을 확인했다.
- 원본 전체 화면 PNG 4장을 `work/screenshots/original`에 보존하고 SHA-256을
  `workspace/graphics/catalog/screen_catalog.json`에 기록했다.
- 확인 화면은 타이틀 겸 메인 메뉴, 옵션, 등장인물 선택, 사용 무기 선택이다.
- 확인 원문에는 `ストーリー・モード`, `オプション`, `難易度`,
  `登場人物選択`, `使用武器選択`, `打刀`, `重量 1.5kg`,
  `全長 92.0cm`이 포함된다.
- 제목과 화면 헤더·이름표는 장식된 판형 그래픽으로 보인다. 다만 화면의
  외형만으로 TIM 또는 특정 DAT 자산이라고 확정하지 않았으며, 현재 상태는
  `classified`이다.
- 무기명과 제원은 선택에 따라 바뀌는 영역이므로 고정 배경보다 동적
  문자열·글리프 렌더러일 가능성도 남아 있다. 다른 무기 선택 화면을 같은
  구도로 비교해야 경로를 좁힐 수 있다.

## 상태 비교 캡처 (2026-07-29)

- 새 원본 PNG 2장을 추가 수집해 전체 캡처는 6장이 됐다.
- 메인 메뉴 캡처는 기존과 동일한 `ストーリー・モード` 선택 상태였다.
  따라서 메뉴 선택·비선택 변형 비교는 아직 미완료다.
- 무기 선택은 `打刀`(`重量 1.5kg`, `全長 92.0cm`)와
  `レイピア`(`重量 0.9kg`, `全長 75.0cm`)를 비교했다.
- 육안 구조 비교에서 `使用武器選択`, `重量`, `全長` 라벨과 정보판 틀은
  유지되고 무기명·숫자·무기 그림이 함께 바뀐다.
- 이 결과는 무기 정보 화면이 단일 완성 배경 한 장만으로 구성된다는
  가설에는 맞지 않는다. 고정 UI와 선택별 자산 또는 동적 렌더링이 합성되는
  혼합 경로를 우선 후보로 둔다.
- 전체 화면 픽셀 해시는 시간에 따른 캐릭터 포즈와 영상 후처리까지 포함하므로
  렌더 경로 판정 근거로 사용하지 않는다. 다음 단계는 디스크 후보 자산과
  화면 구성 요소를 개별적으로 연결하는 것이다.

## 메인 메뉴 상태 비교 (2026-07-29)

- `対戦モード` 선택 상태의 원본 PNG 한 장을 추가해 전체 캡처는 7장이 됐다.
- 기존 `ストーリー・モード` 화면과 비교하면 타이틀 로고와 하단 선택 프레임은
  유지되고 프레임 안의 메뉴 문구가 교체된다.
- 따라서 타이틀 화면 전체가 메뉴별 완성 이미지 한 장씩 바뀐다고 볼 근거는
  약해졌다. 공통 배경·프레임 위에 선택별 라벨 그래픽 또는 동적 글꼴 출력이
  합성되는 경로를 우선 후보로 둔다.
- 화면 비교만으로 두 라벨이 별도 TIM인지, 아틀라스의 다른 영역인지, 문자열과
  글리프 렌더러인지 확정할 수 없다. 다음 조사는 디스크 자산 후보에서 두
  라벨을 함께 설명하는 저장 구조를 찾는 것이다.

## 화면 앵커 자산 연결 (2026-07-29)

- 349개 논리 파일에서 정확한 Shift-JIS 화면 원문 6종을 검색했다.
  `対戦モード` 한 건만 `SLPM_860.20` 파일 오프셋 7,928에서 발견됐지만,
  문맥은 메뉴가 아니라 메모리카드 제목
  `［対戦モードにカッツェ見参！］`였다.
- 유효한 표준 TIM 3,696개를 검증·디코드해 접촉 시트로 대조했다.
- 현재 화면과 일치하는 메뉴·헤더·무기 정보 TIM을
  `DATA3/O12.DAT`, `DATA3/O04.DAT`, `DATA3/O02.DAT`에서 확인했다.
- 메뉴 라벨은 선택별 4bpp TIM이며, 무기명과 제원은 무기별 224×64 정보판
  TIM 한 장에 함께 구워져 있다.
- 대표 UI에 대해서는 표준 TIM 그래픽 경로가 확정됐다. 다만 동일 자산의
  중복 가능성과 실제 로더·VRAM 소비는 아직 추적하지 않았으므로,
  수정본 인게임 PoC 전에는 전체 경로 검증 완료로 보지 않는다.
