# 확인된 형식과 좌표

## 디스크

- 원본 표현: CUE + raw BIN
- 트랙: 단일 Mode 2/2352
- 파일시스템: ISO 9660
- 파일 데이터: Form 1과 Form 2 혼합

다음 좌표를 혼용하지 않는다.

1. raw BIN 바이트 오프셋
2. 2352바이트 raw sector LBA
3. Form 1의 2048바이트 사용자 데이터
4. Form 2의 2324바이트 사용자 데이터
5. ISO 파일 내부 오프셋
6. PS-X EXE 적재 후 RAM 주소

## PS-X EXE

| 항목 | 값 |
| --- | --- |
| 파일 | `SLPM_860.20` |
| 파일 크기 | `604160` |
| SHA-256 | `0164189A870BA87495A3C0010ADB85535AE5A798BBD0DD276B88BF24ECC3CEDA` |
| 진입 PC | `0x80070A1C` |
| 적재 주소 | `0x80010000` |
| payload 크기 | `0x93000` |

현재 실행 파일은 0x800바이트 PS-X EXE 헤더 뒤 payload가 이어진다.
확인된 범위에서 파일 오프셋 `f >= 0x800`의 RAM 주소 후보는
`0x80010000 + (f - 0x800)`이다. overlay나 동적 적재 파일에는 이 식을
재사용하지 않는다.

## 그래픽

`DAT` 내부의 TIM 후보는 다음 검증을 모두 통과하기 전까지 확정하지 않는다.

- `0x10` 식별자와 flags 유효성
- CLUT 블록 길이·폭·높이 일치
- 픽셀 블록 길이·폭·높이 일치
- 파일 경계를 넘지 않음
- 다음 블록 또는 컨테이너 레코드 경계와 충돌하지 않음
- 실제 VRAM 업로드와 화면 표시 대응

### 확인된 표준 TIM

`workspace/scripts/scan_psx_tim.py`로 349개 논리 파일을 검사해 CLUT·이미지
블록 길이와 PS1 VRAM 범위를 통과하는 표준 TIM 3,696개를 확인했다. 이는
표준 TIM 모집단이며 압축·커스텀 그래픽까지 포함한 전체 그래픽 모집단은 아니다.

대표 화면과 시각적으로 일치하는 4bpp TIM은 다음과 같다.

| 화면 요소 | 파일 | 파일 오프셋 | 크기 |
| --- | --- | ---: | ---: |
| `ストーリー・モード` | `DATA3/O12.DAT` | `0xB22C` | 352×18 |
| `対戦モード` | `DATA3/O12.DAT` | `0xC758` | 236×18 |
| `オプション` 헤더 | `DATA3/O04.DAT` | `0x3CCC` | 232×16 |
| `登場人物選択` | `DATA3/O02.DAT` | `0x14360` | 232×16 |
| `使用武器選択` | `DATA3/O02.DAT` | `0x14FE0` | 232×16 |
| `打刀` 정보판 | `DATA3/O02.DAT` | `0x1F99C` | 224×64 |
| `レイピア` 정보판 | `DATA3/O02.DAT` | `0x2321C` | 224×64 |

현재 확인은 저장 자산과 화면의 시각 대응까지다. 실제 로더·VRAM 좌표와
수정본 소비는 첫 TIM 교체 PoC에서 검증한다.
