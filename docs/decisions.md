# 설계 결정

## D-001 일본판을 유일한 빌드 기준선으로 사용

- 상태: 채택
- 근거: 사용자가 일본판 기준 작업을 지정했고 `SLPM-86020` 원본을 제공했다.
- 결과: 다른 지역판은 분석용 대조군일 뿐 패치 입력이나 주소 사양이 아니다.

## D-002 기존 한자 폰트 재사용을 선결론으로 두지 않음

- 상태: 채택
- 근거: 대량 평문 문자열과 실제 글리프 공급자가 아직 확인되지 않았다.
  8KB 후보 두 개도 시험한 고정 셀 해석에서 글꼴이 아니었다.
- 결과: 코드→글리프→VRAM→화면 경로를 확인한 뒤 슬롯 전략을 고른다.

## D-003 그래픽 텍스트 PoC를 첫 화면 변경으로 선택

- 상태: 채택
- 근거: 디스크에 다수의 그래픽 컨테이너 후보가 있고, 격투게임의 메뉴·선택
  화면은 고정 라벨일 가능성이 높다. 동일 크기 교체는 디스크 위험도 낮다.
- 폐기 조건: 실제 화면 라벨이 동적 글꼴 경로임이 확인되면 문자열 PoC로
  전환한다.

## D-004 파일 이동보다 동일 크기 제자리 교체 우선

- 상태: 채택
- 근거: 혼합 Form 1/Form 2 디스크이고 숨은 LBA 참조가 아직 배제되지 않았다.
- 결과: 성장·재배치는 참조 완전성과 무변경 왕복을 증명한 뒤 허용한다.

## D-005 메모리카드 제목을 한글 렌더 PoC로 쓰지 않음

- 상태: 채택
- 근거: BIOS 또는 시스템 UI의 문자 표시 성공은 게임 자체 renderer와
  글리프 공급 경로를 증명하지 못한다.

## D-006 고정 크기 4bpp TIM 그래픽 번역 경로 승인

- 상태: 채택
- 근거: `DATA3/O04.DAT`의 옵션 헤더를 `옵션`으로 교체한 수정 BIN이
  정적 무결성 검사를 통과했고 DuckStation 실제 화면에서 표시됐다.
  주변 UI 보존과 메인 메뉴 복귀·옵션 재진입도 정상으로 확인됐다.
- 결과: 동일 제약을 만족하는 `DATA3/O12.DAT` 메뉴와 `DATA3/O02.DAT`
  선택·무기 UI에 이 방식을 확대한다.
- 제한: 다른 DAT, 동적 문자열, 다른 픽셀 포맷, 크기 증가와 파일 이동은
  이 결정으로 승인되지 않는다.
